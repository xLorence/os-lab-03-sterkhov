# 1. Основные сведения

Для просмотра информации использовал:

`cat /proc/$$/status | head -12`

Получил:
```
Name:   bash
Umask:  0022
State:  S (sleeping)
Tgid:   2991
Ngid:   0
Pid:    2991
PPid:   2965
TracerPid:      0
Uid:    1000    1000    1000    1000
Gid:    1000    1000    1000    1000
FDSize: 256
Groups: 24 25 27 29 30 44 46 100 106 111 113 116 1000
```

### Паспорт процесса

| Параметр         |    Значение     |
| ---------------  | --------------- |
|      Имя         |      bash       |
|      PID         |      2991       |
|      PPID        |      2965       |
|      UID         |      1000       |
| Состояние        | S (sleeping)    |
| Исполняемый файл | /usr/bin/bash   |
|Текущий каталог   | /home/daniil247 |


Состояние S означает, что процесс находится в состоянии ожидания.

### 2. Аргументы запуска

Сначала я попытался посмотреть содержимое cmdline с помощью cat и tr. Для более наглядного просмотра использовал:

`od -c /proc/$$/cmdline`

Результат:

```
0000000   b   a   s   h  \0
0000005
```

Это означает, что текущий процесс запущен как bash. Нулевой байт \0 является разделителем аргументов в файле cmdline.

### 3. Исполняемый файл

Командой:

`ls -l /proc/$$/exe`

получил:

`/proc/2991/exe -> /usr/bin/bash`

То есть `/proc/2991/exe` указывает на настоящий исполняемый файл bash.

4. Текущий каталог

Командой:

`ls -l /proc/$$/cwd`

получил:

`/proc/2991/cwd -> /home/daniil247`

Следовательно, текущим каталогом процесса является `/home/daniil247`.

Затем я выполнил:

- `cd /etc`
- `ls -l /proc/$$/cwd`

Получил:

`/proc/2991/cwd -> /etc`

После этого вернулся обратно командой:

`cd -`

и получил:

`/home/daniil247`

Таким образом, при смене текущего каталога изменяется ссылка `/proc/PID/cwd`. Сам процесс bash при этом остаётся тем же, его PID не меняется.

5. Открытые дескрипторы

Для просмотра открытых файловых дескрипторов использовал:

`ls -l /proc/$$/fd`

В результате:

- 0 -> /dev/pts/0
- 1 -> /dev/pts/0
- 2 -> /dev/pts/0

Дескриптор 0 — стандартный ввод.

Дескриптор 1 — стандартный вывод.

Дескриптор 2 — стандартный вывод ошибок.

В данном случае все три дескриптора связаны с терминалом `/dev/pts/0`, поэтому ввод и вывод команд происходят через этот терминал.

### 6. Почему ps и top показывают те же сведения?

ps и top получают информацию о процессах из системных источников, в том числе через интерфейс /proc. Поэтому сведения о PID, состоянии, пользователе и других параметрах процесса совпадают с теми, которые можно увидеть непосредственно в /proc.
