# Задание 3. Зомби-процесс

Для создания зомби была выполнена команда:

`bash -c 'sleep 1 & exec sleep 120' &`

После этого:

`ps -eo pid,ppid,stat,cmd`

В выводе появился:

```
3287  2991  S  bash
3288  3287  S  sleep 120
3289  3288  Z  [sleep] <defunct>
```

Главное здесь:

|  PID | PPID | STAT |        CMD        |
| ---- | ---- | ---- | ----------------- |
| 3289 | 3288 |   Z  | [sleep] defunct   |

Z означает состояние zombie, а <defunct> означает, что процесс уже завершился, но запись о нём ещё остаётся в таблице процессов.

### Почему kill -9 не убивает зомби?

Потому что процесс уже завершился. Он больше ничего не выполняет и не может обработать сигнал. В системе остаётся только информация о его завершении, которую должен забрать родитель.

Поэтому SIGKILL не может «убить» зомби второй раз.

### Почему зомби исчез после завершения родителя?

Родитель должен забрать информацию о завершившемся потомке через wait().

Когда родительский процесс завершается, оставшийся зомби становится сиротой. Его усыновляет процесс PID 1, после чего информация о завершении забирается и запись зомби удаляется.

#### (?) У меня зомби потом действительно исчез из списка процессов, хотя я отдельно его не удалял.

### Чем опасны тысячи зомби?

Один зомби почти не нагружает процессор, но каждый занимает запись в таблице процессов. Если таких процессов накопится очень много, система может исчерпать доступные записи и перестать нормально создавать новые процессы.
